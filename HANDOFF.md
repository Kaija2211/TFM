### D. Manager influence arc, phase 2 — fitness/condition, injuries, reserve pool (`66b863c`)

- Built in the agreed order: **reserve pool first** (the safety net before the risk existed), then Condition, then injuries.
- Reserve pool: 11 players per team (every key position covered at least once), softened 0.85x team strength, generated via a thin `AgentSquadGenerator.GenerateReservePlayer` wrapper around the existing private `GeneratePlayer` — managed team only, lazily generated.
- `Condition` (0-100, persistent across matchdays): decays based on minutes played and Stamina, recovers based on Age — lives in `ManagerSquadRoles`, **not** as a `PlayerAgent` field (deliberately more conservative than section B's stats, since this is actively mutated every matchday rather than inert). Feeds into match performance as a second multiplier stacked on `ManagerFormationFit`'s existing position-fit clone.
- **Bonus fix found along the way**: extending the fit-adjusted clone for Condition surfaced that it had never picked up section B's new stats — a managed-team player playing out of position was silently using 0 for LongShots/ThroughBalls/etc. Fixed as part of the same edit.
- Injuries: risk scales sharply with low pre-match Condition and modestly with Age (1.5% baseline → ~11% for an exhausted veteran, statistically verified over 5000 trials/point). Bell-curve recovery (1-8 matchdays). `EnsureNoInjuredStarters` auto-swaps any still-injured starter for the best fit bench cover (or calls up a reserve) before every managed-team fixture — the squad can never actually be left unable to field a position.
- **A real compile bug was caught and fixed here**: `System.Random`/`UnityEngine.Random` ambiguity in the new injury code (this file has both `using System;` and `using UnityEngine;`) silently blocked Play Mode entirely for a while, traced back through `Unity_GetConsoleLogs` after several confusing/misleading RunCommand errors pointed elsewhere. See `feedback_random_namespace_ambiguity` — **always fully-qualify `UnityEngine.Random`** in `ManagerPrototypeController.cs` specifically.

## 4. Gotchas learned this session (save yourself the rediscovery time)

- **`System.Random`/`UnityEngine.Random` ambiguity is a real `CS0104` compile error**, not a tooling quirk — `ManagerPrototypeController.cs` has both `using System;` and `using UnityEngine;`. Always write `UnityEngine.Random.value`/`UnityEngine.Random.Range(...)` fully-qualified in that file. When a `Unity_RunCommand` script fails with a confusing error against known-correct code, check `Unity_GetConsoleLogs` for the *real* project compile state before assuming it's a caching/staleness issue — it may be a genuine error elsewhere that's silently blocking everything, including Play Mode entry (which reports success from the tool's side even when Unity can't actually enter Play Mode).
- **Point anchor + a `sizeDelta`/`anchoredPosition` snapshotted once from another rect's `.rect.width`/`.rect.height` goes stale on window resize.** Hit twice now on the same Matchday Prep pitch element (horizontal position in an earlier session, vertical height this session). Prefer stretch anchors, or a center-point anchor (0.5) with fixed pixel offsets on either side — both recompute automatically on every layout pass and are immune to this regardless of aspect ratio or how many times the window resizes.
- **A popup/dropdown nested inside its own trigger element renders behind later siblings**, full stop, regardless of `SetActive(true)` — Unity draws UI children in sibling order. Build popups as a sibling of whatever they're near, call `transform.SetAsLastSibling()` at the moment they open.
- **TMP labels built while their GameObject hierarchy is inactive can permanently fail mesh generation** (`characterCount` stuck at 0) — the general `RecoverBlankLabelsNextFrame` sweep does not reliably repair this even with `includeInactive: true`, since `ForceMeshUpdate()` on a label that's never been through `OnEnable` doesn't behave the same as one that has. Populate dynamic TMP content lazily, only once the container is actually active — don't build it ahead of time while hidden.
- **`Random.State` save/restore is the established, verified-safe technique** for adding new randomness to `AgentSquadGenerator.cs` without shifting the shared RNG sequence Research Mode depends on. Reuse it for any future generation addition there; always follow up with a same-seed regeneration check (two fresh generator instances, same `Random.InitState`, confirm existing stats byte-identical).
- **`DesignSync` can read an existing claude.ai/design project by the UUID in its URL** (`get_project` → `list_files` → `get_file`) — use this whenever Thomas references a mockup by link, rather than eyeballing proportions from a screenshot.
- Carried forward, still true: `Unity_RunCommand` script edits sometimes need an actual Play Mode restart (not just a recompile) to take effect in an already-running session; fully-qualify `UnityEngine.UI.Image` in RunCommand scripts (namespace collision in that sandbox); no save/load system exists, so always check before restarting Play Mode if there's visible in-progress state.
